# Render thread and GPU costs on the Redmi K50 Ultra, round 2 (2026-10-17)

中文：[2026-10-17-perf-round2.zh-CN.md](2026-10-17-perf-round2.zh-CN.md)

This picks up after [2026-10-17-frame-overlap.md](2026-10-17-frame-overlap.md); that note's frame overlap (PR #9) is the starting point. Measured 11:30–14:35 NZDT on the Redmi K50 Ultra (Adreno 730, Vulkan 1.1, Android 15). Build `android/linux-build`; engine changes on branch `android/perf-round2`.
- **Scene:** the same camp scene as before: cold start, Play on the saved Sorceress, last four 60-frame `NVN PERF v=1` windows.
- **Markers:** `gfx-defer-events=2` and `gfx-present-overlap=1` are on in every row.
- **Temperature:** the phone was left on the home screen for 30 minutes whenever the battery passed about 36 °C. Every comparison below is between runs at similar temperature; the battery temperature is noted per row.
- **Tools:** simpleperf on the device (`simpleperf record --app`, cpu-clock, DWARF call graphs), the engine's per-pass GPU timer (`gfx-pass-profile`), and the counters added on the way (below).

## Result

| Step | Battery °C | Camp fps | CPU submit ms | GPU ms |
|---|---|---|---|---|
| Start: frame overlap (PR #9) | 32 | 19.7 | 41.6 | 41.6 |
| Timing scopes on 1 frame in 8; command-range cache | 35 | 21.2 | 37.5 | 42.0 |
| Color images without `MUTABLE_FORMAT` (UBWC kept) | 33 | 23.8 | 33.7 | 36.2 |
| Framebuffers kept across frames; per-slot command pools; less heap churn | 27 | 24.3–24.7 | 32.1 | 36.6 |
| Texel-buffer descriptor sets memoized (`gfx-texel-memo=1`) | 31 | 25.6–26.1 | 27.4 | 36.8 |
| One occlusion query per run of draws; snapshot and image front caches | 28 | **32.3–33.1** | 22.7–23.3 | **25.2** |

**Camp: 19.7 → 33 fps. 3D character select: 24.7–27 → 39–40 fps.** The picture stayed the same as the default build in every step (screenshots compared in the same scene).

## Findings

1. **The timing scopes read the clock about 95,000 times per frame.**
   - simpleperf put 19.3% of the render thread in `__kernel_clock_gettime`, at about 105 ns per read.
   - The per-part breakdown (`NVN PERF parts`) now runs on one frame in 8. Marker `gfx-perf-sample=N` changes that; `1` restores every frame.
2. **`VK_IMAGE_CREATE_MUTABLE_FORMAT_BIT` on every color image, with no format list, turns off UBWC on Adreno.**
   - Dropping it cut GPU time by 5.8 ms and CPU time by 3.8 ms (less memory traffic shared with the CPU).
   - **No view ever used a different format** across boot, menus, character select and the camp. The Metal backend made the same choice for Apple GPUs: in its own counts, 0 of 17,473 textures needed one.
   - A differing view now upgrades the image in place, as `tex_upgrade_pfv` does in `nvn_mtl.m`: a new image with the flag, a copy of every level and layer, the old image and views retired, and the descriptor memo dropped.
   - `gfx-mutable-test=N` forces the upgrade on every Nth image: 156 upgrades in a camp run, picture unchanged.
   - `gfx-mutable-images=1` restores the old behaviour.
3. **Framebuffers were created and destroyed for every pass of every frame.**
   - That was 5.3% of the render thread; `vkResetCommandBuffer` took another 3.6%.
   - The allocator took about 15%: the Adreno driver `calloc`s inside `vkCmdDraw*`, plus the engine's per-draw vectors and map nodes.
   - Framebuffers of cached render passes now live until the first of their images is destroyed. Each slot has its own command pool, reset whole. `create_pass` reuses its vectors.
4. **558 of 2,188 draws per frame rebuilt their descriptor set every time**, about 21 µs each against about 2.5 µs for a memo hit. The memo excluded uniform texel buffers.
   - All 558 bind one texel range of about 1 MB, which the game rewrites every frame.
   - With `gfx-texel-memo=1` each slot keeps a resident copy, refreshed when its content changes, before its first read in a frame. It is verified once per submission instead of on every hit; hashing it per hit cost 37 ms per frame on the first try.
   - Every draw now hits the memo; the descriptor part fell from 9.6 to 5.4 ms.
5. **Occlusion queries were the largest single GPU cost.**
   - After the game's first `ResetCounter`, every draw got its own precise occlusion query, about 2,200 per frame.
   - Recording none (diagnostic `gfx-no-occlusion`) took GPU time from 36.8 to 26.1 ms and CPU from 27.4 to 23.7 ms.
   - The counters still have to be right: on Metal, reports of 0 made the game cull campfires and lights.
   - As Metal counts per render pass, a query now covers a run of draws. The run ends with the pass, at a counter reset, and at a report (which ends the pass), so a report still sums exactly the draws since its reset. That leaves 48 queries per frame.
   - The main 3D pass went from 19.1 to 12.9 ms, and the UI pass from 3.7 to 1.3 ms.
   - In these scenes the game resets the samples counter 21 times per frame and reports only timestamps (4 per frame) on this path.
6. **Main pass and resolution (before the occlusion fix).** Lowering the 3D scale from 0.75 to 0.6 took the main pass only from 19.6 to 16.8 ms. Most of its cost did not scale with pixels; the per-draw queries explain that.
7. **Storage write tracking (`gfx-wtrack=1`, now through the host's fault hooks):**
   - it copies about 22 KB per frame instead of 18.7 MB (6–8 dirty pages of three 19.6 MB buffers) and takes about 1 ms off the snapshot part;
   - the effect is not visible in the total yet, so it stays opt-in.

## Where the frame goes now

- **The frame is CPU bound at about 30 ms:**
  - submit 22.8 ms;
  - present 1.7 ms;
  - about 5.5 ms of the game's own code on the same thread.
- **GPU: 25.2 ms.**
- **Biggest CPU parts per frame:** snapshot copies 5–6 ms, draw setup 5.7 ms, descriptor 5.4 ms, the command loop 3.5 ms, pipeline lookup 2.4 ms.

## Markers added (files in `files/dm/`)

| Marker | Default | What it does |
|---|---|---|
| `gfx-perf-sample` = N | 8 | per-part timing on one frame in N; 0 = off |
| `gfx-mutable-images` = 1 | off | create every color image with `MUTABLE_FORMAT`, as before |
| `gfx-mutable-test` = N | off | force the in-place upgrade on every Nth color image (test) |
| `gfx-no-persistent-fb` | off | per-slot framebuffers, as before |
| `gfx-no-slot-pools` | off | the shared command pool and `vkResetCommandBuffer`, as before |
| `gfx-texel-memo` = 1 | off | resident texel copies; memoize their descriptor sets |
| `gfx-query-per-draw` = 1 | off | one occlusion query per draw, as before |
| `gfx-no-occlusion` = 1 | off | diagnostic: no occlusion queries; reports read 0 |
| `gfx-wtrack` = 1 | off | storage write tracking |
| `gfx-readback-cached` = 1 | off | readback arenas in host-cached memory (not measured yet) |
| `env` | none | `KEY=VALUE` lines set before the app's defaults, such as `DM_3D_SCALE=0.6` |

## Next

- **Run the texel memo more widely** (other acts, combat, menus), then make it the default.
- **Overlap the game's own ~5.5 ms with translation.** This means auditing the asynchronous translation path, which Android keeps off: object lifetimes between the game thread and the translation thread.
- **Pipeline lookup:** the key is rebuilt from the full create info on every draw (2.4 ms).
- **Readback in cached memory:** 1.3 MB of storage results per frame are read back from uncached memory.
